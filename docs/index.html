SIPTestWin

Herramienta profesional de pruebas SIP (RFC 3261) para Windows, inspirada en SIPp: interoperabilidad, conformidad de protocolo, carga controlada y robustez — desde PowerShell, CMD o CI, sin WSL ni máquina virtual Linux.

Uso autorizado. SIPTestWin es para sistemas que posees o tienes permiso explícito para probar. Aplica lista blanca de destinos, límites de tasa/concurrencia/duración, modo simulación por defecto, confirmación antes de pruebas activas, redacción de credenciales y registro de auditoría. No incluye fuerza bruta, inundación sin límites, fraude telefónico ni explotación automática de terceros.

Motor SIP

Máquina de estados de transacciones y diálogos, temporizadores y retransmisión UDP.

Métodos

OPTIONS · REGISTER · INVITE · ACK · CANCEL · BYE, con Digest.

Transportes

UDP, TCP y TLS opcional.

Escenarios

Subconjunto XML compatible con SIPp + forma integrada.

Instalación

Requiere Python 3.12+. Crea el entorno virtual fuera de carpetas sincronizadas (OneDrive) para evitar bloqueos de archivos.

py -m venv C:\Users\tu_usuario\.venvs\siptestwin
C:\Users\tu_usuario\.venvs\siptestwin\Scripts\Activate.ps1
pip install --upgrade pip
pip install -e .            # dependencias de ejecución
pip install -e ".[dev]"     # + pytest y pyinstaller

Comprueba la instalación y el entorno:

siptestwin version
siptestwin doctor
doctor valida la versión de Python, las dependencias, el enlace de sockets UDP y muestra avisos de firewall/puertos de Windows.

Es una herramienta de línea de comandos, no una app con ventana. No la abras con doble clic (la consola parpadea y se cierra). Ejecútala desde PowerShell.

Ejemplo de principio a fin (loopback)

# Terminal 1 — servidor de prueba local
siptestwin testserver --port 55060

# Terminal 2 — validar, simular y ejecutar
siptestwin validate-config   --config config\example.yaml
siptestwin validate-scenario --file scenarios\basic_call.xml
siptestwin run --config config\example.yaml --scenario scenarios\basic_call.xml ^
  --host 127.0.0.1 --port 55060 --calls 3            # simulación
siptestwin run --config config\example.yaml --scenario scenarios\basic_call.xml ^
  --host 127.0.0.1 --port 55060 --calls 3 --execute  # transmite de verdad

Overrides por línea de comandos

--host --port --transport --scenario --calls --concurrency --call-rate
--output-dir --authorize <host|cidr> (repetible)
--execute   # enviar paquetes (por defecto: simular)

Escenarios

Documentos XML que describen un flujo UAC. Subconjunto documentado de SIPp más una forma integrada cómoda.

Elementos

ElementoUso

Parametrizar INVITE y modificar headers

Hay dos niveles, combinables. El de escenario (por <send>) tiene prioridad sobre el global.

1 · Por escenario (recomendado)

Dentro de un <send request="INVITE"> (o cualquier método integrado) puedes añadir, sobrescribir o eliminar headers y reemplazar el cuerpo:

<send request="INVITE">
  <header name="Subject">SIPTestWin custom INVITE</header>
  <header name="Priority">urgent</header>
  <header name="X-Test-Id">[call_id]</header>        <!-- placeholder -->
  <header name="User-Agent">SIPTestWin-Lab/0.1</header>
  <header name="Allow" action="remove"/>             <!-- eliminar header -->
  <body content-type="application/sdp"><![CDATA[
v=0
o=siptestwin 0 0 IN IP4 [local_ip]
s=Custom Session
c=IN IP4 [local_ip]
t=0 0
m=audio 40000 RTP/AVP 0
a=rtpmap:0 PCMU/8000
a=sendrecv
]]></body>
</send>
  • <header name="X">valor</header> — añade o sobrescribe el header X.
  • <header name="X" action="remove"/> — elimina el header X.
  • <body content-type="…">…</body> — reemplaza el cuerpo; Content-Length se recalcula solo.
  • Valores de header y body admiten placeholders ([call_id], [local_ip], [$var], …).

Escenario de ejemplo incluido: scenarios/invite_custom.xml.

2 · Global por configuración

Aplica a todas las peticiones integradas de la ejecución (útil para marcar un run de CI o cambiar el SDP por defecto):

message:
  extra_headers:                 # añadidos a toda petición integrada
    Subject: "SIPTestWin test"
    X-Lab: "ci-run-42"
  remove_headers:                # eliminados de toda petición integrada
    - "User-Agent"
  invite:
    content_type: "application/sdp"
    extra_headers:               # añadidos solo al INVITE
      Priority: "urgent"
    sdp: |                       # cuerpo SDP personalizado (sustituye al generado)
      v=0
      o=siptestwin 0 0 IN IP4 [local_ip]
      s=Custom Session
      c=IN IP4 [local_ip]
      t=0 0
      m=audio 40000 RTP/AVP 0
      a=rtpmap:0 PCMU/8000
      a=sendrecv

Precedencia

De menor a mayor: headers base → message.extra_headers → message.invite.extra_headers (solo INVITE) → <header> del escenario. Las eliminaciones (config y luego escenario) se aplican al final.

Pruebas de robustez: eliminar un header obligatorio (p. ej. Via o Call-ID) es posible a propósito para comprobar cómo responde el servidor, pero romperá la correlación de respuestas (el motor enruta por Call-ID), así que esos casos suelen terminar en timeout — comportamiento esperado.

Verificar y ejecutar

siptestwin validate-scenario --file scenarios\invite_custom.xml
siptestwin run --config config\example.yaml --scenario scenarios\invite_custom.xml ^
  --host 127.0.0.1 --port 55060 --calls 1 --execute

Trazar / capturar mensajes SIP

SIPTestWin puede registrar cada mensaje SIP enviado y recibido en tres destinos combinables:

  • Consola — una línea por mensaje (escalera de la llamada), con opción de mensaje completo.
  • Texto — un .trace.log legible con marcas de tiempo (los hashes de credenciales se redactan).
  • pcap — una captura que se abre en Wireshark; no necesita tshark ni npcap. Cada mensaje se envuelve en Ethernet/IPv4/UDP sintéticos para que Wireshark lo diseccione como SIP.

Por configuración

capture:
  enabled: true
  console: true        # una línea por mensaje en pantalla
  console_full: false  # imprimir también el mensaje completo
  text: true           # escribir <file>.trace.log
  pcap: true           # escribir <file>.pcap (Wireshark)
  file: "results/mytrace"   # base; por defecto results/trace-<timestamp>

Por línea de comandos

siptestwin run -c config\example.yaml --scenario scenarios\basic_call.xml ^
  --host 127.0.0.1 --port 55060 --execute ^
  --trace-console --pcap --trace-file results\mytrace

# Genera: results\mytrace.trace.log  y  results\mytrace.pcap
# Abre el pcap en Wireshark para ver toda la señalización SIP.
FlagEfecto
--captureEscribe el .trace.log de texto.
--pcapEscribe el .pcap para Wireshark.
--trace-consoleImprime cada mensaje en consola.
--trace-fullCon --trace-console, imprime el mensaje completo.
--trace-file <base>Ruta base de salida.
SIP Digest nunca transmite la contraseña en claro, así que el pcap (captura real del cable) no contiene secretos en texto plano; aun así, en la traza de texto se redacta el response= por coherencia con la política de auditoría.

Elegir la IP local (origen)

La IP de origen (usada en Via/Contact y para el enlace del socket) es execution.local_host. Lista las IPs disponibles en esta máquina y elige una, o pon una manualmente:

siptestwin interfaces
#    Local IPv4 addresses
#  +--------------+----------+
#  | IP           | Type     |
#  | 192.168.1.26 | private  |
#  | 192.168.56.1 | private  |
#  | 127.0.0.1    | loopback |
#  +--------------+----------+

siptestwin run -c config\example.yaml --local-host 192.168.1.26 ...

Si la dejas sin definir, se autodetecta la IP de la ruta por defecto. También puedes fijarla en el YAML (execution.local_host) o pasarla manualmente con --local-host.

Seguridad

  • Lista blanca explícita: una ejecución activa se rechaza si target.host no está en security.authorized_targets. Vacío = nada autorizado; una IP privada no implica autorización.
  • Ejecución acotada: calls, concurrency, call_rate y duration_seconds tienen topes forzados (100000 / 500 / 500/s / 86400s).
  • Modos: simulación por defecto (no transmite); --execute transmite tras mostrar destino/límites y pedir confirmación.
  • Credenciales: solo se responde a un desafío Digest legítimo con credenciales de laboratorio; se redactan de logs/reportes. Sin adivinación ni fuerza bruta.
  • Auditoría: cada ejecución activa añade líneas a <output_dir>/audit.log.
  • XML/YAML seguro: se rechazan DOCTYPE/entidades (sin XXE), regex acotada, yaml.safe_load.

Build del ejecutable (Windows)

pip install pyinstaller
pyinstaller --onefile --name siptestwin ^
  --collect-submodules siptestwin ^
  --paths src ^
  src\siptestwin\__main__.py

dist\siptestwin.exe version
dist\siptestwin.exe doctor

Para distribuir sin Python, entrega dist\siptestwin.exe junto con tus config\*.yaml y scenarios\*.xml.

Si el arranque de --onefile es lento o el antivirus lo marca, usa --onedir y distribuye la carpeta dist\siptestwin\ completa.

Métricas y reportes

Cada ejecución genera JSON y/o CSV en results/ y un resumen en consola con:

  • Mensajes enviados/recibidos, retransmisiones, timeouts, errores de transporte.
  • Respuestas por categoría (1xx…6xx) y latencia p50/p95/p99.
  • Transacciones completadas/fallidas y llamadas intentadas/establecidas/terminadas.
  • Motivos de fallo, diferenciando fallo del servidor de error local del generador.
